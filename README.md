> **Production-grade Dockerfile linter, multi-stage validator, security scanner, and automated autofixer.**

Eliminate root execution privileges, unpinned base images, hardcoded secrets, package manager bloat, and broken multi-stage references with single-command autofixes.

---

## ⚡ Highlights

- 🛡️ **Container Security Auditing**:
  - Detects missing non-root `USER` (`SEC001`, CWE-250).
  - Detects unpinned tags and mutable `:latest` base images (`SEC002`).
  - Detects dangerous curl/wget piping to shell scripts (`SEC003`, CWE-494).
  - Detects hardcoded secrets in `ENV` and `ARG` (`SEC004`, CWE-798).
  - Flags unnecessary `sudo` execution in container build layers (`SEC005`).
  - Enforces `HEALTHCHECK` instructions on exposed network services (`SEC006`).
- ⚡ **Automated In-Place Autofixing (`fix`)**:
  - Safely injects `--no-install-recommends` and cleans `/var/lib/apt/lists/*`.
  - Appends `--no-cache-dir` to `pip install` and `--no-cache` to `apk add`.
  - Converts local `ADD` instructions to safe `COPY` instructions.
  - Corrects relative `WORKDIR` paths to canonical absolute paths.
  - Automatically provisions non-root `USER 10001` before container entrypoints.
  - Generates unified diffs and previews changes before modifying files.
- 🏗️ **Multi-Stage Build Graph Analysis (`scan`)**:
  - Validates stage names and detects duplicate definitions (`MS004`).
  - Detects missing stage targets in `COPY --from=<stage>` (`MS001`).
  - Detects forward and cyclic stage references (`MS002`).
  - Identifies orphaned, dead build stages (`MS003`).
  - Generates ASCII dependency hierarchy trees.
- 📊 **Security Grading & SARIF Reporting**:
  - Computes 0–100 security health score with letter grades (A+ to F).
  - Generates GitHub-native **SARIF 2.1.0** reports for direct ingestion into GitHub Code Scanning security alerts.
  - Supports machine-readable JSON and human-friendly terminal output.
- 📦 **Zero External Runtime Dependencies**:
  - 100% pure Python standard library. Lightning-fast execution in pre-commit hooks and CI pipelines.

## 🚀 Quickstart & CLI Commands

### 1. `dockerfile-doctor lint`
Inspect your Dockerfile for security risks and best-practice violations:

```bash
# Lint current directory Dockerfile
dockerfile-doctor lint

# Lint specific Dockerfile
dockerfile-doctor lint path/to/Dockerfile

# Lint from stdin in CI pipes
cat Dockerfile | dockerfile-doctor lint -

# Output GitHub SARIF 2.1.0 report
dockerfile-doctor lint --format sarif Dockerfile > results.sarif

# Enforce strict zero-warning policy
dockerfile-doctor lint --strict Dockerfile
```

### 2. `dockerfile-doctor fix`
Automatically fix identified issues:

```bash
# Preview fixes as a unified diff (dry-run)
dockerfile-doctor fix Dockerfile

# Apply fixes directly in-place
dockerfile-doctor fix -i Dockerfile

# Apply specific rule fixes only
dockerfile-doctor fix -i --rules PERF001,PERF002,PERF004 Dockerfile
```

#### Example Diff Generated by `dockerfile-doctor fix`:
```diff
--- a/Dockerfile
+++ b/Dockerfile
@@ -1,6 +1,7 @@
 FROM python:3.11-slim
-WORKDIR app
-ADD requirements.txt .
-RUN apt-get update && apt-get install -y curl
-RUN pip install -r requirements.txt
+WORKDIR /app
+COPY requirements.txt .
+RUN apt-get update && apt-get install -y --no-install-recommends curl && rm -rf /var/lib/apt/lists/*
+RUN pip install --no-cache-dir -r requirements.txt
+USER 10001
 CMD ["python", "app.py"]
```

### 3. `dockerfile-doctor scan`
Run a comprehensive security and multi-stage dependency scan:

```bash
dockerfile-doctor scan Dockerfile
```

Sample output:
```text
============================================================
        DOCKERFILE SECURITY & ARCHITECTURE SCAN
============================================================
Target File    : Dockerfile
Total Stages   : 2
Security Score : 100/100 [Grade: A+]
Issues Found   : 0 errors, 0 warnings, 0 notices
Autofixable    : 0 issue(s)

--- Multi-Stage Build Dependency Graph ---
Stage 0: FROM golang:1.22-alpine AS builder (✓ non-root)
Stage 1: FROM alpine:3.19 AS runner (✓ non-root) [FINAL]
  └── depends on: Stage 0

✓ No security or configuration issues detected!
============================================================
```

Enforce quality gates in CI builds:
```bash
# Fail if score drops below 90
dockerfile-doctor scan --fail-under 90 Dockerfile

# Fail if grade is below A
dockerfile-doctor scan --strict Dockerfile
```

## 🐍 Python Library API

Use `dockerfile-doctor` programmatically in Python applications:

```python
from dockerfile_doctor import (
    parse_dockerfile_content,
    lint_dockerfile_content,
    fix_dockerfile_content,
    scan_dockerfile_content,
)

content = """
FROM python:3.11-slim
WORKDIR app
ADD requirements.txt .
RUN pip install -r requirements.txt
CMD ["python", "app.py"]
"""

# 1. Lint
diagnostics = lint_dockerfile_content(content)
for diag in diagnostics:
    print(f"[{diag.severity}] Line {diag.line}: {diag.title}")

# 2. Autofix
fixed_content, diff, applied_fixes = fix_dockerfile_content(content)
print(diff)

# 3. Security Scan
report = scan_dockerfile_content(content)
print(f"Grade: {report.grade}, Score: {report.security_score}/100")
```

## 🤖 GitHub Actions Workflow Example

Integrate `dockerfile-doctor` directly into your GitHub Actions CI pipeline:

```yaml
name: Security & Dockerfile Audit

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  dockerfile-doctor:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dockerfile-doctor
        run: pip install dockerfile-doctor

      - name: Run Dockerfile Linter & Generate SARIF
        run: dockerfile-doctor lint --format sarif Dockerfile > dockerfile-doctor.sarif
        continue-on-error: true

      - name: Upload SARIF to GitHub Code Scanning
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: dockerfile-doctor.sarif

      - name: Enforce Security Quality Gate
        run: dockerfile-doctor scan --fail-under 85 Dockerfile
```
